# M6–M7 使用与发布手册

## 手机和平板主控

Android、iOS 和 iPadOS 以 Flutter 提供连接服务设置和应用生命周期，使用系统 WebView 加载同源 Web 主控。Rust WASM 配对和 WebRTC 媒体与浏览器共用。被控电脑继续使用桌面端。

1. 在两端设置同一个 HTTPS 目录服务。手机端通过右上角设置保存，产品默认地址可在构建时注入。
2. 在手机输入被控电脑的九位设备 ID 和六位密码。首次连接时核对设备指纹，由被控端批准需要的输入、声音、剪贴板或文件等权限。
3. 触控板模式以单指移动光标，直接触控模式按画面位置点击。轻点为左键，长按为右键，可显式按住和松开左键。双指可滚动、捏合缩放和放大后平移。点“键盘”打开软键盘和常用键栏，外接键盘可在画面获得焦点后使用。平台支持文本输入权限时直接输入。已授权剪贴板时可显式把文本送到远端剪贴板。
4. 切到后台会释放已按下的键和鼠标键。应用前台恢复后，网络中断时会短时间尝试恢复原会话，再次验证密码、设备指纹和一次性会话令牌，维持原权限上限。系统回收页面或恢复超时后重新连接。文件面板的本地目录能力由系统 WebView 提供。

私有局域网部署也使用手机能访问且系统信任的 HTTPS 地址。公网或跨网连接所需的 TURN 与桌面和浏览器共用。Android 构建的目标 API 为 36。部署到设备时依旧受系统 WebView 版本、证书与网络授权影响。[自托管部署](m4-m5.md) · [Android 本地网络权限](https://developer.android.com/privacy-and-security/local-network-permission?hl=en)

## 桌面后台与访问授权

在“设置 → 维护”管理用户登录后启动、托盘和诊断。Windows 使用当前用户的启动项，macOS 13+ 使用登录项，Linux 使用 XDG Autostart。关闭窗口时，已成功显示托盘的应用会继续接收。Linux 托盘依赖可嵌入 GTK 状态图标的 X11 桌面，系统不显示图标时关闭窗口会正常退出。

在被控端的「设置 → 共享 → 接入方式」可选择每次确认、可信设备免确认或密码验证后连接。密码接入适用于通过 OPAQUE 验证的 ID 和 IP 桌面会话。实际权限取决于本机允许的权限和系统能力。远程 Shell 始终由本机单独批准。

采用可信设备方式时，在主控端开启「设置 → 权限 → 使用本机设备授权」。首次接入在被控端勾选「信任此设备 30 天」并批准权限。重连继续验证密码和设备密钥，信任按局域网或设备 ID 目录保存。申请新权限需要重新批准。切换接入方式会结束正在按旧策略自动授权的会话。主控设备密钥保存在系统凭据库。

后台运行使用已登录用户的桌面、系统捕获和输入权限。锁屏、安全桌面、登录前、系统屏幕选择器和 Wayland 权限仍由操作系统管理。系统不可采集或不可输入时，远控能力随平台状态变化。

诊断可查看、复制或清除最近 128 条本机连接事件。诊断包含应用版本、平台、接收状态、时间、方向和结果分类，省略设备身份、地址、密码、密钥和媒体内容。保存过的密码继续由操作系统的凭据库管理，未保存密码的近期记录可直接清除。

## 私有监控

`NEXDESK_METRICS_LISTEN` 可配置独立的回环监听。Compose 默认在目录容器内启用 `127.0.0.1:54001`。采集在线宿主、未完成和已就绪的信令路由，以及发起路由或握手的成功、不可用、限流、无效、超时和错误计数。

```sh
docker compose -f deploy/compose.yaml exec directory curl -fsS http://127.0.0.1:54001/metrics
```

信令路由表示握手流程，媒体经由 WebRTC 建立。对于 coturn，设置 `NEXDESK_TURN_METRICS=1` 后，从 TURN 主机的 `127.0.0.1:9641` 采集实际中继资源和流量。Caddy 继续转发现有健康检查和客户端路由。发布时保留监控端口的回环绑定。[coturn 监控参数](https://github.com/coturn/coturn/blob/master/README.turnserver)

## 构建和签名

| 平台 | 构建入口 | 签名入口 |
| --- | --- | --- |
| Windows x64 | 根目录的 `tools/m1/build-windows-preview.ps1 -FlutterRoot <SDK> -Configuration Release`。运营默认目录可用 `-DefaultDirectory` | 使用 `-SigningThumbprint` 选定代码签名证书，可用 `-TimestampUrl` 请求 RFC 3161 时间戳。脚本校验三个 NexDesk 原生文件的 Authenticode 签名 |
| Linux | 在对应 Linux 上构建 Rust agent 和 FFI，再用 `flutter build linux --release`。将 agent 和 `libnexdesk_ffi.so` 放在 bundle 可执行文件旁 | 使用下方的 Ed25519 便携包工具 |
| macOS | 在原生架构的 Mac 上运行 `bash tools/release/package-macos.sh`，编译并打包 Flutter、Rust agent、FFI 和 CLI | 配置 `NEXDESK_MACOS_SIGN_IDENTITY` 和 `NEXDESK_NOTARY_PROFILE` 以完成 Developer ID 签名与公证 |
| Android | 从 `apps/desktop` 运行 `flutter build apk --debug` 生成开发测试包，或 `flutter build appbundle --release` 生成发布包 | 用 `NEXDESK_ANDROID_SIGNING_PROPERTIES` 指定外部签名属性文件，提供 `storeFile`、`storePassword`、`keyAlias`、`keyPassword` |
| iOS / iPadOS | 在 macOS 从 `apps/desktop` 运行 `flutter build ipa` | 在 Xcode Runner 选择发布者团队、实际 Bundle ID 和分发描述文件，根据分发渠道配置 IPA 导出 |
| Web / 目录 / CLI | `tools/m4/build-web.sh`、`deploy/compose.yaml`、`cargo build --locked --release -p nexdesk-cli` | 目录与 CLI 可通过签名便携包分发。HTTPS 服务证书在部署时配置 |

移动和标准 Flutter 桌面构建的运营默认地址可用 `--dart-define=NEXDESK_DEFAULT_DIRECTORY=https://desk.example.test`。携带自托管配置的版本仍可在客户端内更换服务。

Windows 上遇到 JDK 的 `Unable to establish loopback connection` 且栈包含 `UnixDomainSockets` 时，可在本次构建的 JVM 参数设置 `-Djdk.net.unixdomain.tmpdir=<可写短路径>`。本轮使用项目的 `target/tmp` 验证了 JDK 21 的选择器及 Gradle 回环启动。

生成第三方声明时，使用本次构建的依赖缓存与锁文件。将以下命令的输出随包分发，按目标调整 Rust 平台和原生 SDK 声明路径。

```sh
python tools/release/notices.py THIRD-PARTY-NOTICES.txt \
  --rust-target x86_64-pc-windows-msvc --flutter --web \
  --extra libwebrtc PATH_TO_SDK_LICENSE --extra Flutter PATH_TO_ENGINE_LICENSE
```

## 便携包升级与回滚

版本工具需要 Python 3.12+ 和 OpenSSL 3。发布者长期保存 Ed25519 私钥，部署端独立保存可信公钥。每一版签入版本、目标平台、协议号及全部文件列表、长度和 SHA-256。客户端/服务程序退出后再切换版本，数据目录保留在应用版本目录外。

```sh
python tools/release/portable.py package PAYLOAD nexdesk.zip --version 0.1.0 \
  --target windows-x64 --entrypoint nexdesk_desktop.exe --protocol 1 --key release-private.pem
python tools/release/portable.py verify nexdesk.zip --key release-public.pem
python tools/release/portable.py install INSTALL_ROOT nexdesk.zip --key release-public.pem
python tools/release/portable.py launch INSTALL_ROOT --key release-public.pem
python tools/release/portable.py rollback INSTALL_ROOT --key release-public.pem
```

版本完整性检查通过后，工具才会更新当前版本指针。回滚重新验证上一个激活版本，然后保留原数据目录。Windows、Linux 的登录项指向配置时的程序路径，便携版切换到不同目录后需在新版本的“维护”重新保存登录项。macOS App Bundle 使用系统签名与公证归档，Android 和 iOS 通过各自的系统分发渠道安装。M6–M7 保留目录协议 v1 和既有桌面控制协议。与旧版主机互控时使用常规连接，设备授权选项需要双方支持。

## SQLite 备份与恢复

`SOURCE` 和 `TARGET` 分别指文件路径。默认桌面文件名为 `desktop.sqlite3`。目录文件为部署配置 `NEXDESK_SIGNAL_DB`。后者使用 `--kind directory`。

```sh
python tools/release/database.py backup SOURCE SNAPSHOT --kind desktop
python tools/release/database.py restore SNAPSHOT TARGET --kind desktop --stopped --before PRE_RESTORE_COPY
```

备份可在线执行。恢复前退出桌面应用或停止目录服务。覆盖现有数据前须生成新的还原前快照。恢复桌面配置后需重新批准无人值守设备。恢复目录时会保留当前可读取数据库中的撤销记录。若原库损坏无法读取，可从快照恢复到另一个新文件并保留原文件，核对恢复点之后的撤销情况。密码和设备私钥继续由原系统凭据库保管。备份目录服务时也单独保留部署配置和 Caddy 证书卷。

## 发行验收

移动端真机验收包括 Android 与 iOS/iPadOS 的 HTTPS、中文输入/外接键盘、音频、锁屏、横竖屏、网络切换。桌面发布还应分别验证各系统登录启动、托盘行为、系统权限撤销、真实双端互控及发行签名。
