# 实施计划与发布门槛

阶段按可验证交付划分。M0 之后的工期需根据 M1 的硬件、UI 纹理与安全协议原型估算。需求编号与验收动作见 [功能清单](features.md)。

## 里程碑

| 阶段 | 工作内容 | 依赖与交付标准 |
| --- | --- | --- |
| **M0 工程基座** | 功能、架构、交互、规范和计划文档；Cargo workspace；Rust 连接类型、FFI 和独立 CLI；Flutter Windows/macOS/Linux 入口和首页 | Windows 上构建并验证 Rust、Flutter 与 ABI；其他平台具备工程入口，在对应系统构建验证后记录 |
| **M1 纵向验证** | 用最小被控进程和主控验证同一套 H.264/VP8、Opus、WebRTC。并行验证三平台捕获、硬解纹理、浏览器播放、LAN 端口和 PAKE | 主机和浏览器可用同一轨道；Rust/Flutter 能显示持续画面；验证指纹绑定与拒绝逻辑；产生带机器、版本和驱动的基线数据 |
| **M2 桌面 LAN 内测** | 完成桌面权限、IP/端口/密码、身份和近期设备、看屏、键鼠、多显示器、连接恢复和系统凭据 | 3×3 互控通过；断公网成功；错误密码、授权拒绝、撤销、断线、失焦、转屏和会话退出有验收证据 |
| **M3 日常远控功能** | 音频、质量/帧率控制、分辨率事务与记忆、文本剪贴板、双栏文件、任务恢复及性能指标 | 通过音画、输入、文件及显示模式验收；带大文件任务的输入延迟达标；4 小时稳定性测试有结果 |
| **M4 ID、浏览器和自托管** | Rust 目录/信令、TURN、浏览器客户端、内网 HTTPS、离线部署和兼容矩阵 | 同一部署下可通过设备 ID 连接；跨网直连和中继回退通过；核心浏览器能力与权限降级有验收记录 |
| **M5 独立终端与 Pi** | ID 连接、密码输入、独立打包、ANSI/Kitty/Sixel、缩放/平移、本地命令模式、Pi；单独交付可授权 Shell | 脱离 Flutter GUI 构建并在对应终端连接；前后台、能力退化和退出恢复验证；Shell 默认关闭并通过授权测试 |
| **M6 移动主控** | Flutter 工程扩展，触控板、软键盘、外接输入、声音与前后台、网络恢复；移动端只担任主控 | iOS/iPadOS、Android 真机验证三桌面被控端，复用服务与协议，保留移动发布矩阵 |
| **M7 发布和长期维护** | 托盘/自启、已授权的无人值守能力、安装签名、升级回滚、备份恢复、依赖许可清单、版本兼容、故障处理 | 桌面/Web/CLI 每项核心功能通过发布矩阵；提供可重建的客户端、自托管发布物和独立的移动发布路径 |

M1 后媒体与权限路径稳定才扩展会话 UI。M2 后可由不同开发者并行推进 M3 文件/音频和 M4 Web/信令。M5 依赖设备 ID 链路与原生接收器，移动端依赖会话协议及平台媒体集成。单人开发按依赖顺序交付可测里程碑，多团队按媒体平台、客户端、服务协议和发布测试分工。

## M1 工作包

Windows 选定窗口、H.264/VP8、Opus、Flutter 纹理、Chrome 和 OPAQUE 已有联调结果。Windows 硬解纹理、双机断公网、macOS 与 Linux 实机等仍按以下工作包验收。

M2 的被控授权、直连会话、输入、系统凭据和近期设备已接入。M3 增加了媒体设置、分辨率事务、文本剪贴板和文件协作。

| 工作包 | 实施与验证 | 必须产出的证据 |
| --- | --- | --- |
| Windows 媒体链路 | DXGI 或 WGC → D3D11/Media Foundation → libwebrtc → Flutter Texture 和浏览器。测回退、设备重置及资源释放 | 捕获、编码、解码和展示耗时，硬件状态，以及参考机器和构建配置 |
| macOS 和 Linux 风险验证 | ScreenCaptureKit/VideoToolbox 授权及句柄；GNOME Wayland Portal/PipeWire/EIS 和 Linux X11 接入 | 平台权限操作记录，测试版本、已知能力差异、软编/软解后备路径 |
| 局域网端口和身份 | 本地监听、IP 候选、断公网、六位密码配对、信令保护、已知设备重连 | 端口策略与协议决策记录，认证失败、限速、身份变化、超时和拒绝测试 |
| 协议与观察 | 连接阶段时间线、媒体统计、状态错误码、构建版本以及弱网条件 | 可重复的运行脚本、测试环境配置、运行日志和量化目标复核 |

计划为 Windows x64、macOS 14+ Apple Silicon 和 Ubuntu 24.04 x64 相应桌面环境建立首批测试机。macOS Intel、其他 Linux 发行版、Windows 版本和 CPU 架构的支持以单独通过为准。Linux 初始验证 GNOME Wayland 与 X11，各项能力分别记录。Web 完整功能先覆盖桌面 Chrome/Edge，再核对 Firefox/Safari 核心远控与降级行为。

## 按依赖推进的工作清单

### M1 先验证三条链路

1. 固定可重复构建的 libwebrtc 修订，定义主控接收、被控发送和硬件编解码工厂边界，生成最小 C ABI。
2. 在 Windows 完成单显示器采集、一个视频轨道及 Flutter 纹理，记录捕获到呈现时间。使用同一被控端连接 Chrome，验证 H.264/VP8 协商及浏览器播放。
3. 在 macOS、Linux 验证各自的采集授权和硬解呈现路径。确认可带入生产的颜色格式、纹理或帧缓冲所有权、回退方式和 CPU/GPU 资源占用。
4. 并行验证离线 LAN、端口、六位密码握手和 WebRTC 指纹绑定。将加密库版本、信令边界、测试向量及失败行为写入协议决策记录。
5. 评审实测证据，确定兼容范围、安装体积和常驻资源预算，排定功能实现顺序。权限或媒体链路未满足参考场景时，完成对应技术验证后再扩大功能开发。

### M2 交付能每天使用的 LAN 内测

1. 接上本机监听、接口设置、冲突处理和关闭策略。加入被控用户进程、授权提示与连接活动状态。
2. 把 M0 的两个前端入口接到同一会话 API。桌面完成密码授权、IPC、近期设备及本机凭据库；CLI 保留独立构建。
3. 完成输入映射、组合键、释放、断线恢复、多屏切换和图形权限处理，串通进程退出和资源清理。
4. 验证三平台 LAN 互控与硬件/软件回退。记录所有拒绝状态和主控可采取的恢复操作。

### M3 完成日常协作

1. 增加系统音频、质量/帧率控制和可测指标。优化拖动与静态文本，测画面刷新、编码队列和硬件资源。
2. 加入显示器模式事务、记忆与回滚，验证 DPI、旋转、热插拔和本机操作优先级。补齐中文输入、组合键和文本剪贴板。
3. 实现有根目录授权的文件浏览、块传输、双栏及任务模型。先验证单文件，再加递归、拖放、重名策略、断点续传和限速。
4. 通过携带大文件任务的音频、输入和画面验收，记录性能及资源预算。

### M4 上线自托管实例和浏览器主控

1. 发布最小目录与信令服务，验证主机注册、ID 寻址、短期会话和设备撤销。部署同源 HTTPS 和 coturn。
2. 实现 Web 主控、权限和错误显示。验证 Chromium 本地目录授权及 Firefox/Safari 的降级交互。原生主控按同一设备身份规则接入 ID。
3. 在仅内网、两端不同网络及直连失败三种条件运行。完成部署文件、健康检查、备份恢复和协议兼容记录。

### M5 和 M6 交付其他主控入口

1. 先建立独立 CLI 会话驱动，默认只读；依次加入图形能力探测、视口、输入、本地命令模式和包发布。验证 Pi 只走本地进程接口并处理正常退出/断线。
2. 在独立授权下加入 Shell，通过明确的普通用户凭据和进程生命周期控制访问，验证撤销和 PTY 清理。
3. 复用 Flutter 应用组件和 Rust SDK 交付移动主控。先验证手机的触控及软键盘，再验证平板、外接键盘、音频和系统前后台。移动验收和桌面发布可分别推进。

### M7 固化可发布版本

1. 验证实际支持的自启、托盘、系统权限恢复和无人值守策略。以发布矩阵公布被控能力与操作系统约束。
2. 固定构建环境和签名流程。跑升级、回滚、长连接、权限撤销与故障恢复；形成可下载产物及可自托管发布物。
3. 整理测试、诊断、运维和依赖声明。以测试记录关闭功能清单条目，报告仍需平台专项验证的能力。

## 端到端验收

| 场景 | 方法 | 目标 |
| --- | --- | --- |
| 清晰度和流畅性 | 参考机器、有线 LAN、RTT ≤ 5 ms，1080p/60 Hz，两端可用硬件路径，使用滚动、拖动和文本阅读场景 | 动态场景接近 60 FPS。首轮延迟目标 P50 ≤ 80 ms、P95 ≤ 120 ms；统计延迟使用输入到显示的测量 |
| 资源 | 空闲、静止、动态、双向传输场景记录整机和应用 CPU/内存/GPU、传输和安装体积 | M1 取得基线，M2 在相同工具链上确定预算，并提供后续比较 |
| 网络和音频 | 记录延时、丢包、乱序、带宽下降和中继；校验音画同步和输入响应 | 弱网能合理降档，网络恢复后恢复画面；音频和输入具备独立错误状态 |
| 权限 | 新设备、可信设备、重新配对、过期令牌、会话撤权、系统权限取消 | 身份或授权不明确时拒绝；本机可看见和停止会话；释放输入和相关资源 |
| 多屏与分辨率 | 横屏、竖屏、不同 DPI、切换、热插拔、确认超时、主动断开 | 坐标一致；记忆只来自实际生效且确认的模式；恢复尊重本机后续修改 |
| 文件 | 多层目录、空目录、重名、大文件、断网、空间不足、暂停/取消、源文件变化 | 内容校验一致、任务可恢复；越界和权限不足拒绝；大文件传输下输入与音频达标 |
| 终端 | ANSI / Kitty / Sixel、窄窗口、tmux/SSH、有界输出、Pi 挂载与退出 | 终端按能力降级，本地命令和远端输入边界明确；CLI 独立运行 |
| 安装与恢复 | 全新安装、升级、降级/回滚、眠醒、换网、锁屏、服务重启、长连与频繁开关 | 关键行为符合发布矩阵，故障能定位，更新不丢身份和授权 |

## 发布清单

1. 用同一提交保存各平台安装包签名、架构、依赖版本和发行说明。
2. 附兼容矩阵、部署、受信任 HTTPS、局域网端口及恢复手册。开源许可证和第三方声明与发布物一致。
3. 运行桌面互控、Web/CLI、离线直连、TURN、带文件负载和撤销权限的验收。重要失败场景有可重现记录。
4. 更新能力版本及最小兼容版本，完成 SQLite 配置备份和回滚验证。
5. 对仍受系统或驱动限制的功能如实列出可用范围，并在界面使用能力状态提示。
