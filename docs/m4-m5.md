# M4–M5 构建、部署与使用

设备 ID 连接由桌面、浏览器、独立 CLI 和 Pi 共用。目录负责查找设备、转发 OPAQUE 及加密后的 SDP 信令，并发放 TURN 临时凭据。媒体、键鼠和文件经 WebRTC 在主控与被控之间交换。LAN 模式继续使用独立地址、密码和历史。

## 最小本机环境

Windows 桌面包包含桌面程序和独立 CLI。目录服务和 Web 资源位于独立的自托管包。解压自托管包并运行目录下的 `nexdesk-signaling.exe`，本机入口为 `http://127.0.0.1:54000`。默认将目录数据库保存到启动时的工作目录。Linux 和 HTTPS 安装见[自托管部署](deployment.md)。

浏览器需要 Node.js 24、Rust 的 `wasm32-unknown-unknown` 目标、可编译该目标的 Clang 和发行包中匹配的 `wasm-bindgen 0.2.130`。在仓库根目录执行以下命令。PowerShell 可用 [build-web.ps1](../tools/m4/build-web.ps1)，其中 `-WasmBinary` 可传入先在 WSL 或 Linux 生成的 WASM。

```sh
rustup target add wasm32-unknown-unknown
cargo install --locked wasm-bindgen-cli --version 0.2.130
bash tools/m4/build-web.sh
cargo build --locked --release -p nexdesk-signaling
target/release/nexdesk-signaling
```

默认服务监听 `127.0.0.1:54000`，从 `apps/web/dist` 提供页面。原生端和页面共用 `http://127.0.0.1:54000` 作为本机开发目录。在第二台电脑上访问时使用下述 HTTPS 部署。

## 自托管 HTTPS 和 TURN

Linux 的 Compose 发布模板包括 Rust 目录、Caddy 和可选 coturn。将 [配置示例](../deploy/.env.example) 复制为 `deploy/.env`。将 `NEXDESK_HOST` 设为两端均可解析的内网域名，将 `NEXDESK_HTTPS_BIND` 设为部署机面向用户的接口。Caddy 安装默认本地证书链，浏览器和原生端都需要信任对应根证书。可在 [Caddyfile](../deploy/Caddyfile) 中提供组织已有的证书。信令的 54000 端口留在容器网络内，Caddy 只向目录传递其观察到的客户端 IP。[Caddy 官方镜像](https://hub.docker.com/_/caddy) · [coturn 官方镜像](https://hub.docker.com/r/coturn/coturn/)

```sh
docker compose --env-file deploy/.env -f deploy/compose.yaml up -d --build
docker compose --env-file deploy/.env -f deploy/compose.yaml exec https cat /data/caddy/pki/authorities/local/root.crt
```

在客户端的证书管理器中导入确认无误的根证书后访问 `https://<域名>/healthz`，应返回 `{"ok":true,"protocol":1}`。配置 `NEXDESK_ENROLLMENT_KEY` 后，新主机首次注册也要在进程环境中带相同的注册口令。已有设备用其注册密钥校验身份。注册口令与用户配对用的六位密码用途不同。

跨网时将 `NEXDESK_TURN_URLS` 配为两端可达的 TURN 地址。UDP 和经 TCP 连接 TURN 可用空格分隔，如 `turn:relay.example.test:3478?transport=udp turn:relay.example.test:3478?transport=tcp`。目录和 coturn 共用一个至少 32 字符的随机 `NEXDESK_TURN_SECRET`。部署模板使用 Linux 主机网络，需允许 3478 TCP/UDP 和 49160–49259 UDP。位于静态 NAT 后的 coturn 可通过 `NEXDESK_TURN_EXTERNAL_IP` 配置公网地址与本地地址映射。外层防火墙可继续限定中继网段。

```sh
docker compose --env-file deploy/.env -f deploy/compose.yaml --profile turn up -d --build
```

常规配置允许 ICE 直连及回退到中继。`NEXDESK_ICE_RELAY_ONLY=1` 可在验收时要求经 TURN。包含静态页面、WASM 和目录程序的镜像可以配合代理及 TURN 镜像离线导入。内网 DNS 和证书信任仍需在该网络内可用。

### 备份和撤销

`nexdesk-signaling backup DATABASE NEW_FILE` 生成事务一致的 SQLite 快照，也能在目录服务运行时使用。目标文件须是新路径。把快照复制到另一个受控存储。恢复时先停止目录进程，保留现有数据库及 WAL，再用快照恢复同一目录来源的注册库和 Caddy 证书卷。被控端会重新注册在线状态。旧版本备份不会包含备份之后的撤销记录。

`nexdesk-signaling revoke DATABASE DEVICE_ID` 撤销该注册设备。在线检查在心跳窗口内生效，现有 ID 会话也会关闭。被控端的“撤销当前会话”可直接终止本次连接和输入权限。

## 连接电脑

1. 桌面应用打开后自动准备本机连接。ID 模式使用发行版预配置的目录，或在“设置 → 连接”启用自托管并填写服务器地址和信令 HTTPS 端口。两端各保存一次同一地址。端口留空时使用 443。部分自托管部署要求注册口令，启动被控端应用时在本地进程环境中设置 `NEXDESK_ENROLLMENT_KEY`。
2. B 的 ID 显示在线后，A 在首页输入该九位 ID，点击“连接”并提交 B 对应模式的密码。密码可保存在系统凭据库。浏览器打开同一个目录的 HTTPS 首页并输入 ID 和密码。命令行被控可使用 `nexdesk-agent host --listen 127.0.0.1:53980 --screen <编号> --directory https://desk.example.test`，用 `nexdesk-agent sources screen` 查找编号。
3. 桌面主控会记录首次通过密码验证并出画面的设备身份，重连时自动核对。浏览器和终端按提示核对指纹。被控端根据「设置 → 共享 → 接入方式」批准会话，实际授予的权限由主控请求、本机权限上限和系统能力共同决定。浏览器初次播放声音需要用户操作。文件权限由被控端选择的共享目录限制。具备文件系统选择器的浏览器可以双向递归传文件夹，其余浏览器可选文件上传和显式下载单文件。浏览器普通下载缓存限制为 64 MiB，流式下载使用浏览器授权的目标文件或目录。
4. 局域网来访默认可用。切换到“IP 直连”即可查看本机实际监听地址和另一组密码。A 输入该地址，端口省略时使用 53980。“设置 → 连接”可以选定私网网卡或修改本机监听端口。ID 目录离线不影响这条连接路径。

### 发行版的默认 ID 服务

在实际部署并验证 HTTPS、注册和 TURN 后，使用 `--dart-define=NEXDESK_DEFAULT_DIRECTORY=https://已部署域名` 构建 Flutter 桌面客户端。Windows 打包脚本 `tools/m1/build-windows-preview.ps1` 的 `-DefaultDirectory` 接受同一个根地址。开发构建可用回环 HTTP，供两台电脑访问的部署使用受信任的 HTTPS。

Compose 默认使用内网证书。拥有公网 DNS 和 443 入口的部署可用 `NEXDESK_CADDYFILE=./Caddyfile.public` 申请公开信任的证书。需要自定义外部 HTTPS 端口时，同时设置 `NEXDESK_HTTPS_PORT` 和包含端口的 `NEXDESK_SIGNAL_ORIGIN`，并使用已受信任且匹配域名的证书。自托管配置保持独立，发布包未预设默认服务时仍可设置自己的目录。

## 终端主控

在对应桌面操作系统上准备原生 WebRTC SDK 后可以独立构建。可执行文件不依赖 Flutter 应用包。

```sh
cargo build --locked --release -p nexdesk-cli
nexdesk-cli view https://desk.example.test 012345678
nexdesk-cli view https://desk.example.test 012345678 --control --audio --render kitty
```

密码输入无回显。首次连接按提示核对指纹，也可以用已通过可信渠道得到的完整指纹作为 `--pin`。会话初始只处理本地命令，声音初始静音。`--control` 向被控端申请键鼠权限，主机同意后在终端输入 `control` 才开始转发。按 `Ctrl+G` 释放已按键并回到本地命令，按 `Ctrl+Q` 结束会话。

终端依照环境选择 Kitty、Sixel 或 ANSI。使用 `--render ansi|kitty|sixel|auto` 可显式选择。tmux 或 screen 环境自动使用 ANSI。缩放和平移调整本地视口，点击坐标按同一视口映射到被控端。

| 命令 | 用途 |
| --- | --- |
| `zoom 1`、`zoom 2` | 适配整屏或查看放大细节，最大 8 倍 |
| `pan left`、`pan down` | 平移放大的视口 |
| `monitor`、`monitor 2` | 查看显示器或切换显示器 |
| `quality smooth 45` | 会话画质及帧率，支持 auto、clear、smooth |
| `mute`、`volume 50` | 静音或调整本机播放音量 |
| `stats` | 查看 ICE、媒体格式、帧数及丢帧 |
| `control`、`quit` | 恢复获准的控制或退出 |

### Pi 扩展

Pi 1.6 可用 `pi -e /path/to/NexDesk/extensions/pi/index.ts` 加载扩展。将 `nexdesk-cli` 放入 PATH，或通过 `NEXDESK_CLI` 指定完整路径。输入 `/nexdesk`，选择权限并在组件中输入密码和核对指纹。Pi 负责绘制视口及焦点管理，独立 CLI 负责认证和解码。本地 JSON 行协议仅经子进程的标准输入输出，支持画面、视口、键鼠、命令和释放事件。关闭组件时会结束子进程。

### 独立授权的 Shell

被控端可在「设置 → 共享」中开启“允许在 ID 连接中请求远程 Shell”。命令行被控可在 `--directory` 之外显式传入 `--allow-shell`。主控使用 `nexdesk-cli shell https://desk.example.test 012345678`，被控端确认本次 Shell 请求。

普通用户的进程令牌和授权到位后，主机会建立独立的 Windows ConPTY 或 Unix PTY。Windows 进程纳入专属 Job Object。Unix 会终止 PTY 进程组和仍在该 PTY 会话中的进程。撤销授权或断开时关闭 PTY，Shell 权限需要重新批准。终端输出允许常用显示控制序列，并拦截可改写主控端剪贴板、窗口状态和发起本地终端查询的序列。
