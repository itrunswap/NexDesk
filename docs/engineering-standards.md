# 代码风格与工程规范

代码评审以正确性、可诊断性和平台可维护性为主。这里的命令覆盖当前工程。涉及会话、协议、媒体和平台的条款随这些模块实现生效。

## 仓库、工具链和提交

- 源码和文档使用 UTF-8、LF 和文件末尾换行。提交 Rust 和 Flutter 应用的锁文件、各平台模板工程。保留生成器声明的文件，忽略构建产物和本地缓存。
- Rust 使用 2024 edition。当前最小语言版本由 `Cargo.toml` 声明；开发环境按 [README](../README.md) 的已验证版本配置。Flutter renderer 与 native runner 由支持的 SDK 生成。发布 CI 固定并记录具体 SDK、架构及媒体引擎修订。
- 每次变更覆盖一个可说明的行为，主体描述触发条件、结果和针对性验证。跨端协议、身份、权限、持久化、ABI、第三方依赖变化在评审中明确兼容与迁移。
- 依赖最少、用途明确，优先使用维护良好的基础库和平台 SDK。审查许可证、依赖漏洞、目标平台、发布产物和版本更新策略。安全敏感依赖的变更附上验证记录。
- 公开 API、存储迁移和跨进程消息需要兼容性说明。稳定编号和 ABI 状态码只增补或经版本迁移修改。

## Rust

- `rustfmt` 作为排版标准。类型及 trait 使用 `PascalCase`，变量和模块使用 `snake_case`，常量使用 `SCREAMING_SNAKE_CASE`。用领域名称表达含义，如 `DisplayId`、`InputLease`、`LanEndpoint`。
- 解析和边界检查优先构造可验证的类型。端口使用非零整数，设备 ID 保持字符串语义，文件路径区分虚拟根和系统路径。外部输入校验后才创建资源。
- 库接口使用 `Result<T, Error>` 及明确错误类型；二进制入口将错误映射为退出码和人类可读信息。网络、文件、凭据和用户输入的失败按预期处理。仅在有证明的不变量或测试断言中使用 panic 类操作。
- 控制任务拥有取消令牌、超时和有界队列。阻塞系统调用移到工作线程。互斥锁守卫生命周期尽量短；跨 `await`、回调或系统 API 时明确线程约束。停止会话时先停止输入接收和释放已按键，再结束捕获、传输等资源。
- 领域和 CLI crate 禁止 `unsafe`。FFI 和系统适配把 `unsafe` 限制在小边界，紧邻调用写明指针、长度、对齐、对象所有权、回调寿命和线程前置条件。以安全接口向上提供已检查的值。
- 避免通用公共工具箱及预设复用层。出现两个真实调用方或需要替换实现时再提取稳定边界。

## Flutter / Dart 与 Web / TypeScript

- Dart 使用 `dart format` 和 `flutter analyze`。目录和文件使用 `snake_case`，类型 `UpperCamelCase`，成员 `lowerCamelCase`。工具栏、卡片及表单提取具名小组件，各自负责可读的状态和交互。
- 组件输入不可变，约束和校验结果由共享核心提供。加载失败、待授权、空列表、重连和取消均有可见状态。焦点、控制器、订阅及 Native 句柄跟随会话和 Widget 生命周期释放。
- 可见错误映射到本地化文案，错误码与日志保留结构。统一主题、间距、类型和交互状态；通过键盘可以切换模式、遍历表单和执行主操作。布局验证不同 DPI、窄窗口和系统明暗主题。
- Dart FFI 负责控制、状态和有界输入。视频使用原生 Texture，跨语言只传有定义的句柄、帧元数据和生命周期事件。
- Web 使用 TypeScript 严格模式、明确的类型缩小、Eslint 与 Prettier。React 视图按功能组织。媒体由浏览器原生 WebRTC 播放；关闭会话时清理事件监听、媒体轨道和临时对象 URL。共享协议产物从版本化定义生成。
- `apps/agent/web` 是 M1 的同源验证页，由被控程序嵌入原生 ES 模块和 HTML，可随 Rust 构建复测。正式 Web 应用按上述 TypeScript 和 React 规范实施。

## 原生 SDK、FFI 与进程接口

- Rust 直接调用系统 API 为默认路径。libwebrtc 工厂和运行时对象用 C++ 桥接。Objective-C/Swift、Kotlin 处理平台 SDK 生命周期和必要的桥接。桥接接口记录为什么需要、调用方和线程模型。
- C ABI 导出带 `nexdesk_` 前缀的函数。整数宽度、指针加长度、错误码及结构布局在头文件声明。ABI 显式版本化。Rust 捕获和翻译可恢复错误，任何异常均在各自语言边界内处理。调用双方约定分配/释放函数，回调注销后确保没有迟到调用使用已释放内存。
- per-frame 句柄文档写清所有者、读写权限、复用时间和同步点。复用 GPU 资源前等待生产者/消费者要求的同步；CPU fallback 在统计记录原因。
- 本地 IPC 实施 OS 用户/会话限制、消息上限和操作白名单。状态变更以协议中的确认结果为准。客户端按钮禁用属于 UX，主机必须执行权限检查。

## 协议、安全和存储

- 认证库、SDP 指纹绑定和密码生命周期单独评审。保持会话并发、重试和授权有界。网络输入、系统事件和文件元数据均视为外部输入。
- 运行日志记录错误码、阶段和关联 ID。密码、私钥、令牌、完整 SDP、视频、剪贴板及文件内容不得入日志。地址、设备名和路径按诊断用途脱敏。
- 结构化存储通过迁移脚本更新，成功事务后才切换配置的可见状态。密码从系统凭据库读取；无法安全保存时返回明确错误。测试用访问码由测试环境提供，避免提交可用密钥。
- 资源上限与取消行为是协议的一部分。目录传输使用背压和同文件系统提交。避免不受限制地遍历目录、解码、等待和积累文件块。

## 质量门槛

在仓库根目录运行 Rust 检查。

```sh
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --locked
```

在 `apps/desktop` 运行 Flutter 检查。

```sh
flutter pub get
dart format --output=none --set-exit-if-changed lib test test_support
flutter analyze
flutter test
```

验证覆盖业务边界。M0 做地址解析、Rust ABI 真实动态库检查及桌面表单和布局测试。之后优先覆盖认证拒绝与撤销、连接状态迁移、分辨率回滚、输入释放、文件断点续传、旧版兼容和媒体性能。硬件路径和平台权限必须在对应真实机器验证。

媒体变更使用同一被控端验证 Rust、Chrome 和 Flutter 纹理，按软件与硬件实现记录实际解码和编码结果。认证变更覆盖正常会话、错误密码、身份变化、篡改和挑战重用。通过[各端运行与打包](build.md)启动对应的主控端和被控端。

合并前确认客户端的正常入口能访问改动，跨平台差异和已知限制有文档，核心检查通过。对引入性能成本的改动说明相同环境下的测量方法和结果；没有测试的系统和驱动需要标记为待验证。
